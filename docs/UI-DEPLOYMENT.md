# Archive YemanY — تحديث الواجهة وإدارة Gemini وسجل النشاطات

## المسارات والنشر

تطبيق Next.js داخل `frontend/`، وتطبيق FastAPI داخل `backend/`. لا تضع ملفات الواجهة في جذر المستودع ولا تنشئ مسار `frontend/frontend`.

هذا التحديث **يشمل الخلفية والواجهة معاً**. لا تكفي حزمة الواجهة السابقة لتفعيل إدارة المفاتيح وسجل النشاطات الجديد.

1. خذ نسخة احتياطية لقاعدة البيانات وملفات `.env` والتخزين قبل النشر.
2. حدّث ملفات الكود في مساراتها الحالية دون استبدال الأسرار أو بيانات التخزين.
3. يبدأ التطبيق بإنشاء جدول `gemini_usage` الجديد تلقائياً عبر SQLAlchemy. يوجد أيضاً ترحيل قابل للمراجعة والتشغيل المستقل في `backend/migrations/005_gemini_usage.sql`، يتضمن فهارس لتحسين سجل النشاطات. يُشغّل على قاعدة البيانات الحالية بعد أخذ النسخة الاحتياطية.
4. أعد بناء الخدمتين من جذر المستودع:

```sh
docker compose up -d --build
```

5. عند استخدام GitHub Actions، راجع مسار النشر الحالي الذي يعمل عند التحديث على `main`. لم يُنفّذ نشر إنتاجي ضمن هذا العمل.

## الواجهة

- خط Tajawal محلي عبر npm لجميع النصوص العربية، مع زيادة وضوح البيانات الصغيرة في الجداول والمعاينة.
- الاسم الموحد `Archive YemanY` في الواجهة وعنوان المتصفح وPWA.
- بحث رئيسي واحد واختصار Ctrl+K خارج مساحة النص، وفلاتر بدون تكرار الكلمة المفتاحية ونوع الملف.
- تواريخ نصية إنجليزية `YYYY-MM-DD` مع التحقق من التاريخ الفعلي، لا حقولاً أصلية قد يعكسها المتصفح في RTL.
- تمرير مستقل لقائمة الملفات ولوحة المعاينة. في الهاتف تُختصر أعمدة الجدول دون تمرير أفقي للصفحة.
- طباعة وتحميل وحذف المستند من المعاينة الكاملة فقط، مع نافذة تأكيد للحذف.
- صور مصغرة حقيقية للصور، ورسم الصفحة الأولى من PDF محلياً عبر PDF.js دون الاعتماد على إضافات المتصفح، وأيقونات WORD / EXCEL للملفات الموجودة من هذه الأنواع. **لم تتغير صيغ الرفع والفهرسة المدعومة: ما زالت PDF والصور فقط**؛ لا يدّعي هذا التحديث إضافة OCR لملفات Office.
- زر رفع رئيسي واحد أعلى القائمة الجانبية، وشاشة دخول جديدة دون شارة «النظام نشط» أو نصوص تعريفية إضافية.
- بقيت لوحة الألوان والوضع الداكن كما هما. ذاكرة هيكل PWA الجديدة `archive-yemany-shell-v4`؛ أعد فتح التطبيق المثبت بعد النشر لتفعيل عامل الخدمة الجديد.

## مفاتيح Gemini والعدادات

- من إعدادات الأدمن ← Gemini يمكن إضافة مجموعة مفاتيح، وتعطيلها وحذفها وضبط الحد اليومي ومتابعة الاستهلاك لكل مفتاح.
- يمكن إدخال مفتاح خاص اختياري عند إنشاء الموظف أو تعديله، أو حذفه للعودة إلى مفاتيح النظام. لا تُعاد المفاتيح بنصها الصريح في API.
- الأولوية: مفتاح الموظف ثم مفاتيح النظام بترتيب إضافتها ثم مفاتيح البيئة القديمة إن وُجدت. تعطيل مفتاح نظام يمنع استخدام نسخة البيئة المطابقة له. مفاتيح البيئة ظاهرة للمتابعة وتعديل الحد، لكن إزالتها تتم من إعدادات النشر.
- العدادات مشتركة بين العمليات والخوادم التي تستخدم قاعدة البيانات نفسها، مع حجز طلب ذري داخل معاملة PostgreSQL لمنع تجاوز الحد عند التزامن.
- يحسب العداد **محاولات الطلب من هذا النظام** بما فيها OCR والمحادثة والاختبار والطلبات الفاشلة، وليس استهلاك Google الفعلي أو الطلبات من خارج النظام.
- يعاد ضبط العداد يومياً عند **00:00 UTC** (03:00 بتوقيت اليمن)، تلقائياً عند القراءة أو أول طلب في اليوم الجديد، دون مهمة جدولة يومية أو إعادة تشغيل. لوحة المتابعة تتحدث كل 30 ثانية.
- المتبقي تقديري. قد تشترك عدة مفاتيح في حصة مشروع Google نفسه. رفض الحصة من Google يضع المفتاح في «وصل للحد» حتى اليوم التالي؛ تعطيل المفتاح من المزود يوقف استخدامه ويجرب المفتاح التالي.
- المستندات التي استنفدت جميع مفاتيحها تبقى `queued` وتُعاد محاولتها تلقائياً كل دقيقة على دفعات، مع أقفال تمنع معالجة المستند نفسه بالتزامن. الأخطاء الأخرى تبقى `failed` للمراجعة وإعادة الفهرسة من لوحة الأدمن.

## سجل النشاطات

- تسجيل الدخول والخروج الصريح ومحاولات الدخول الفاشلة وتغيير كلمة المرور.
- إنشاء المستخدمين وتعديلهم وتعطيلهم والصلاحيات ومفاتيحهم؛ دورة حياة الملفات والمجلدات؛ إعدادات النظام ومجموعة المفاتيح.
- بيانات الحدث: اسم الموظف وقت الحدث، التاريخ والوقت، نوع العملية، المورد والتفاصيل والتغييرات الآمنة وعنوان IP إن توفر.
- لا تُخزّن كلمات المرور أو مفاتيح API أو أجسام الطلبات في السجل. أسماء الحقول التي تغيرت لا تتضمن قيم الأسرار.
- فلترة على الخادم حسب الموظف والعملية والتاريخ مع ترقيم صفحات. فلاتر التاريخ حسب UTC، وعرض الوقت حسب المنطقة الزمنية لجهاز المستخدم.
- الطباعة تسجل **طلب طباعة** مصرحاً به؛ المتصفح لا يستطيع التأكد من خروج الورق أو من إلغاء المستخدم نافذة الطباعة.
- تسجيل الخروج يسجل عند ضغط الزر والقدرة على الوصول للخادم؛ إغلاق المتصفح أو انقطاع الشبكة ليس إثباتاً لتسجيل خروج على الخادم. لا يغير هذا التحديث آلية صلاحية JWT الحالية.
- قد يكون عنوان IP هو عنوان الوكيل الداخلي في Docker؛ لا تُقبل ترويسات X-Forwarded-For من عميل غير موثوق. اضبط الوكيل الموثوق في النشر إذا أردت عنوان الجهاز الحقيقي.
- يحتفظ النظام بسجلاته القديمة. لا يمكن استرجاع أسماء أو IP لعمليات لم تكن تسجل سابقاً إلا حيث يمكن ربط المستخدم الحالي.

## التحقق وإعادة تشغيل الاختبارات

```sh
cd frontend
npm ci
npm run lint
npm run build
# في نافذة منفصلة شغّل npm run start ثم:
npx playwright install chromium
npm run test:ui
```

اختبارات المتصفح تستخدم بيانات API مصطنعة للتحقق من RTL والتمرير والمقاسات والفلاتر والهوية والصور المصغرة. ليست اختباراً لخدمة Google.

```sh
python -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
# اضبط أسرار الاختبار المعتادة للتطبيق وقاعدة PostgreSQL مؤقتة مخصصة فقط.
# يجب أن يتطابق TEST_DATABASE_URL وDATABASE_URL وينتهي اسم القاعدة بـ _test.
export DATABASE_URL='postgresql+asyncpg://test_user:password@127.0.0.1:5432/archive_test'
export TEST_DATABASE_URL="$DATABASE_URL"
PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -v
```

اختبارات التكامل تُنشئ بيانات اختبار في القاعدة المحددة وتُرفض إذا لم ينتهِ اسم القاعدة بـ `_test`. لا تشغّلها على الإنتاج. اختبارات المزود تستخدم محاكاة Gemini دون مفاتيح حقيقية أو تكاليف. لا تُضمّن `.venv` أو `node_modules` أو `.next` أو قواعد الاختبار أو الأسرار في Git.

## شبكة المجلدات وHTTPS المحلي عبر Caddy

- المجلدات الآن أيقونات SVG متعددة الطبقات، مستوحاة من شكل ويندوز 11، دون إطار أو بطاقة خارجية دائمة. الاسم وعدد العناصر أسفل الأيقونة؛ العدد يشمل المستندات والمجلدات الفرعية المباشرة.
- الشبكة تتكيف مع عرض المساحة المتاحة: عمودان في الهاتف، ثم 3 و4 و5 وحتى 6 أعمدة. تبقى المجلدات شبكة حتى عند اختيار عرض **قائمة** للمستندات، ويستمر عمل تغيير حجم العرض والسحب إلى المجلد.
- المصدر المشترك للشكل والأدوات: `frontend/app/components/FolderTile.tsx`. الألوان في `frontend/app/globals.css` ضمن متغيرات `--folder-*`، وهي مشتقة من `--brand-primary` وتتبدل تلقائيًا مع الوضع الداكن. تُعرض الأدوات عند التمرير أو التركيز بلوحة المفاتيح؛ وعلى الأجهزة اللمسية تظهر مباشرة لضمان الوصول إليها. كاش الواجهة أصبح `shell-v10`.

### إعدادات HTTPS المثبتة في المستودع

الملف الجذري `Caddyfile`:

```caddyfile
archive-yemany {
    tls internal
    reverse_proxy frontend:3000
}
```

تُنشر المنافذ 80 و443 من خدمة `caddy` فقط لمسار الواجهة، ولم تعد `frontend` تربط منفذ المضيف `80:3000`. بقي منفذ API الخلفي 8000 كما كان؛ لم يغيّر هذا التحديث سياسة نشره. اتصالات المتصفح العادية تظل نسبية `/api/v1` عبر الواجهة، ولا تحتاج فتح 8000 من أجهزة الموظفين.

لتشغيل Caddy مع بقية الخدمات بعد تحديث ملفات المستودع:

```sh
docker compose config --quiet
docker compose up -d --build
docker compose exec caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose logs --tail=100 caddy
```

1. تأكد أن الاسم `archive-yemany` يحل إلى عنوان السيرفر من أجهزة المستخدمين (DNS داخلي أو ملف hosts)، ثم افتح `https://archive-yemany`، وليس عنوان IP مختلفًا عن اسم الشهادة.
2. `tls internal` يستخدم سلطة شهادات Caddy المحلية، لا شهادة عامة موثوقة تلقائيًا. إذا لم تكن الشهادة الجذرية موثوقة بالفعل، وزّع **الشهادة العامة الجذرية فقط** على الأجهزة المخولة بعد التحقق من بصمتها من السيرفر الموثوق. مثال لاستخراجها إلى مجلد Windows المؤقت باستخدام PowerShell:

   ```powershell
   docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt "$env:TEMP\archive-yemany-root.crt"
   ```

   استوردها عبر إدارة شهادات النظام/المتصفح وفق سياسة الشركة. لا تنقل مفاتيح CA الخاصة إلى أجهزة الموظفين ولا تعالج التحذير بتعطيل التحقق من HTTPS.
3. `caddy_data` يحفظ الشهادات وسلطة التوقيع، و`caddy_config` يحفظ إعدادات Caddy التشغيلية، وكلاهما volume دائم. لا تستخدم `docker compose down -v` إن أردت الاحتفاظ بهذه البيانات. خذ نسخة احتياطية آمنة منها؛ أي نسخة من `/data` قد تحتوي مفاتيح خاصة.
4. إذا كان Caddy السابق يستخدم مشروع Compose أو أسماء volumes مختلفة، اربط/انقل البيانات القديمة وفق خطة النشر قبل تشغيل النسخة الجديدة، وإلا ستنشأ سلطة محلية جديدة وتحتاج الأجهزة إلى توثيقها من جديد.
5. يجب أن تكون المنافذ 80 و443 متاحة لخدمة Compose؛ أوقف حاوية Caddy/خادمًا آخر يستخدمها قبل الانتقال إذا كان يعمل خارج هذا الملف.

تم التحقق من تركيب Compose مقابل مخطط Compose الرسمي، ومن تطابق المنافذ والربط والشبكة والـvolumes المطلوبة. بيئة التطوير لا تحتوي Docker أو Caddy، لذلك لم يُنفّذ اختبار TLS أو تشغيل حاويات فعلي هنا؛ أوامر التحقق أعلاه تُنفّذ على السيرفر قبل اعتماد النشر.
