# تحديث واجهة Archive-Yemany

## المسار الصحيح

تُبنى واجهة النظام من مجلد `frontend/` حسب `docker-compose.yml`.
يجب أن يبقى المسار مثل `frontend/app/HomeClient.tsx`، وليس `HomeClient.tsx` في جذر المستودع.

1. فك ضغط حزمة الواجهة محلياً.
2. انسخ مجلد `frontend` المرفق إلى جذر نسخة مستودع `abadi7788/archive-system` مع استبدال الملفات الموجودة داخله. لا تنشئ مساراً إضافياً مثل `frontend/frontend`.
3. لا تستبدل ملفات `.env` أو قاعدة البيانات أو مجلدات التخزين. لا تتضمن الحزمة أيّاً منها، ولا تتطلب هذه التغييرات ترحيل قاعدة البيانات.
4. راجع التغييرات ثم احفظها وارفعها وفق آلية النشر المعتمدة لديك. وجود ملف ZIP وحده في المستودع لا يحدّث التطبيق؛ يجب رفع الملفات بعد فك الضغط في مساراتها الصحيحة.
5. من جذر نسخة النشر شغّل:

```sh
docker compose up -d --build frontend
```

عند الاعتماد على GitHub Actions، يعمل مسار النشر الحالي عند التحديث على `main`؛ لا تغيّر فرع النشر دون مراجعة إعداداتك. لم يتم تنفيذ نشر أو دفع إلى GitHub ضمن هذا التحديث.

## محتويات التحديث

- واجهة موحدة بالكحلي العميق والبترولي والرمادي الفاتح، مع الوضع الداكن.
- خطوط عربية ولاتينية محلية ضمن حزم npm، دون جلب الخطوط من Google وقت التشغيل.
- تحديث شاشة الدخول وشريط التنقل والأرشيف والرفع والإعدادات وسلة المحذوفات ومعاينة المستندات.
- إرسال لغة المستخدم مع طلبات الواجهة الرئيسية وتعريب رسائل أخطاء API العربية والإنجليزية.
- تحديث أيقونات PWA وذاكرة هيكل التطبيق المؤقتة إلى الإصدار `archive-yemany-shell-v3`.

قد يحتاج تطبيق PWA مثبت مسبقاً إلى إغلاقه وإعادة فتحه بعد النشر لتفعيل عامل الخدمة الجديد.

## التحقق المنفذ

- `cd frontend && npm run lint` — نجح فحص TypeScript.
- `cd frontend && npm run build` — نجح بناء Next.js للإنتاج.
- 44 تحققاً برمجياً لترجمات الواجهة واتجاه اللغات ورسائل الأخطاء والجلسات.
- 19 طلب HTTP ناجحاً لصفحات الإنتاج وملفات PWA.
- `git diff --check` — دون أخطاء مسافات.

لم يتم اختبار تسجيل الدخول والرفع وعمليات قاعدة البيانات على خادم الإنتاج؛ لم تتوفر قاعدة PostgreSQL وخدمة الخلفية العاملتان في بيئة التحقق. اختبارات HTTP المذكورة تتحقق من تقديم صفحات الواجهة والملفات، وليست اختبارات تفاعل متصفح أو اختبارات تكامل للخلفية.

لا تتضمن الحزمة `node_modules` أو `.next` أو ملفات الأسرار. شغّل `npm ci` عند تشغيل الواجهة خارج Docker.
